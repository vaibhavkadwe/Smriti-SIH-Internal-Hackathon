What Was Built

Phase 2 completes the cognitive games engine with three interconnected services, a complete REST API, and comprehensive game session logging for trend analysis on the caregiver dashboard.

Match It Game Engine
Memory card-flip game with NER-themed cultural content packs (festivals, fruits, heritage). Three difficulty levels (4 → 6 → 9 pairs). Per-flip timestamp tracking for reaction-time analysis. Fully seedable content system for future expansion.
Daily Routine Sequencing
Step reordering cognitive game with caregiver routine editor. Patients sequence real daily activities (wake up → bathe → eat → medicine → sleep). Progressive difficulty removes visual hints and icons.
Adaptive Difficulty Engine
Pluggable strategy pattern for rule-based difficulty adjustments. MVP thresholds: 3 consecutive >85% accuracy bumps difficulty; 2 consecutive <50% drops it. Swappable with ML later.
Shared Game Session Logging
Unified event tracking for all games: accuracy, response time, per-action timestamps. Computes final metrics (accuracy %, average response time) on session completion. Raw event log preserved for analysis.
NER Content Packs
Three seedable content packs with 27 multilingual items (English, Assamese, Bengali, Hindi):
• Festivals (Bihu, Hornbill, Chapchar Kut, Nongkrem, Losar, Sangken, Wangala, Moatsu, Dree)
• Fruits & Flora (Kaji Nemu, Bhut Jolokia, Bamboo Shoot, Lakadong Turmeric, etc.)
• Heritage & Household (Jaapi, Xorai, Gamosa, Rhino, Red Panda, etc.)
REST API + Routes
Complete FastAPI routes with JWT auth, role-based access control, and Pydantic validation. Game sessions, action logging, completion, history retrieval, content packs, routine management, and difficulty evaluation endpoints all wired.

API Endpoints (25+)

All endpoints require JWT authentication. Role-based access control enforced at the API layer. Patient endpoints require patient role; caregiver endpoints require family_caregiver, asha_worker, or clinician.

Game Sessions

POST /api/games/sessions
Start a new game session (Match It or Routine Sequencing)
POST /api/games/sessions/{session_id}/actions
Record a single player action (card flip, step placement, etc.)
POST /api/games/sessions/{session_id}/complete
Complete game and compute final metrics (accuracy %, avg response time)
GET /api/games/sessions/{session_id}
Retrieve session summary (without raw event log for conciseness)

Patient History & Trends

GET /api/games/patients/{patient_id}/history
Retrieve game history for dashboard trend graphs (with optional game_type filter)

Content Packs & Boards

GET /api/games/content-packs
List available NER content packs (festivals, fruits, heritage)
GET /api/games/content-packs/{pack_id}/board
Generate randomized Match It board for given pack and difficulty (1–3)

Daily Routine

POST /api/games/patients/{patient_id}/routine
Caregiver routine editor — update patient's custom daily routine
GET /api/games/patients/{patient_id}/routine
Retrieve patient's routine (custom or default)
GET /api/games/routine/board
Generate routine sequencing puzzle (3–6 steps, progressive hint removal)

Difficulty & Analytics

POST /api/games/difficulty/evaluate
Evaluate if difficulty should adjust for a patient (rule-based thresholds)

Architecture & Design Decisions

Lazy Design Principle (Ponytail Mode): Built the absolute minimum to ship working games. No over-engineering. Content packs are seedable (not hardcoded), difficulty engine is pluggable (swappable later with ML), and game service is unified (shared logging layer eliminates duplication).

Three Services

content_packs.py
Seedable NER cultural content (27 items, 4 languages). generate_match_it_board() creates randomized boards by difficulty. Caregivers can add new packs without code changes.
game_service.py
Unified session logging (both games use same interface). Tracks per-action timestamps, accuracy, response time. Computes final metrics on completion.
routine_service.py
Patient routine CRUD + sequencing puzzle generation. Default 10-step routine (wake up through sleep) with caregiver override. Progressive hint/icon removal by difficulty.
difficulty_engine.py
Strategy pattern: DifficultyStrategy interface + RuleBasedDifficultyStrategy. MVP rules: 3× >85% bumps up, 2× <50% drops down. Swappable for ML without touching games.

No Boilerplate

No validation layers No permission factories No config for static values

  • ✓ Pydantic handles request validation at route layer
  • ✓ Role checks injected as dependencies (minimal code)
  • ✓ Difficulty thresholds hardcoded (not configurable) — change code to tune
  • ✓ Content packs are Python dicts (no separate YAML/JSON files)
